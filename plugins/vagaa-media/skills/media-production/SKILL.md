## 0. Behaviour rules (2026-09-14, from the pty trial)
1. **Unsupported capability first.** If the user names a model or feature this gateway does not have (sora, runway, kling, veo, seedance, cloud presets that are disabled), say so in ONE sentence before anything else, then offer the local route (presets_list). Never silently substitute and generate.
2. **Vague brief → do not ask, use the defaults and say so (0.9.21; D-358).** "生成一段东西" / "做个视频" with no subject or duration: take the subject from the conversation (or the most obvious reading), leave `seconds` out (the service default), pick `draft`, make it, and in the delivery say in ONE sentence what you assumed ("按 5 秒、主题取了…先出的，要改说一声"). The person only vetoes; never stop to ask before spending the cheap draft. Ask only when nothing in the conversation gives even a guess, or the choice is expensive or irreversible (a `quality` render, a deletion).
3. **Submit, then WAIT, then hand over the WORK NUMBER — and never say the work is made before you hold it.** Until a `job_wait` reply shows `completed` with an `asset_id` (`as-…`), the answer is "still running" with the job id and `eta_s`, never "done". After any `*_submit` / `director_run` / `image_edit` in a turn, wait with `job_wait(job_id)` until `done` is true IN THE SAME TURN; never end the turn asking "要我等它做完吗？" or "shall I wait?" — the person asked for the work, waiting is part of the job (images, BGM, SFX, songs ≤ 1 min and drafts take seconds to minutes). The number you give the person is the **`asset_id` (`as-…`) in the `job_wait` / `*_status` reply**, never the `job_id` (`image-…` / `music-…` / `video-…` / `workflow-…`); call `job_wait` again while `done` is false (follow `next`); once `done` is true, again ONLY when the reply says `asset_pending: true`; `failed` / `lost` = tell the person the `error`; `completed` with neither an `asset_id` nor an asset_pending flag = nothing is indexed for it: follow `next` (the `*_fetch` URL) or say so. Only a job that is genuinely long is a ticket: fast/quality clips, 15 s renders and storyboard/director runs take 5–40 min. Wait with `job_wait(job_id, timeout_s=55)` / `storyboard_wait(run_id)` (server-side long-poll, returns early on change; reply carries `eta_s`, `done`, `next`) — never `sleep`. **Always pass the full `timeout_s=55`**: every call re-sends the whole conversation (one three-picture edit waited on 8 times cost 1.2 M input tokens, 2026-09-23), so call again only when `done` is false (or, rarely, `asset_pending: true`: the job is done but its library row is still being written). At most 3 waits per turn; then END the turn with the job_id / run_id, `eta_s`, and "说一声我再查". NEVER say you are monitoring, polling or watching in the background: you are not; only a person's next message resumes you.
4. **Exact tool names.** Media tools are `mcp__plugin_vagaa-media_media__<tool>` (e.g. `…media__presets_list`, `…media__video_status`); never shorten or hyphenate the prefix.
5. **Results carry the ticket.** Every reply that produced media ends with: asset page URL, job_id, preset + seed, and what to say to iterate.
6. **Editing / swapping / motion transfer have their own tools now**: `image_edit` (change or combine up to 10 existing pictures, Qwen-Image 2.1), `character_swap` (put a reference character into a video, SCAIL-2), `motion_animate` (Wan-Animate-2) — load `image-edit-and-reference` for their contracts; `character_status` / `job_wait` (pass the chain id as `job_id`) follow a chain.
7. **Read the brief forms first.** `presets_list()` answers the brief by default (one screen, ~3K chars); `presets_list(brief=false)` is the 26K-char full contract, only for a missing parameter; `assets_search` rows are brief (`full=true` or `asset_get` for everything). `video_review` frames: 8 is enough for a draft; 16 costs ~4 GiB on the language node.


# Media production on the cluster (core loop)

All media work goes through the `media-mcp` MCP server. Node timings, preset tables, voices, limits and error codes live in
`../_shared/cluster-facts.md` — read it once per task, do not restate numbers from memory. Specialist skills: `video-prompting`
(writing / rewriting / A/B-testing a video prompt), `storyboard-longform` (multi-shot films, continuity, resume, assembly),
`image-edit-and-reference` (references, identity, edits), `music-and-sfx` (BGM, SFX, levels). This skill owns the loop
itself plus speech, translation, the asset library and job recovery. Invoke specialists by the name in the harness skill listing (plugin installs use `vagaa-media:<name>`); loading this core skill does not load their bodies.
Use the exact qualified tool names and input schemas exposed in this session; never invent a namespace or borrow parameters from another tool. A tool intentionally hidden by a planning-only test is not evidence of a production outage.

## 1. Search the library before generating
- `assets_search(query="teapot steam", since="30d")`, `assets_search(query="seed:101 preset:draft")`, `assets_search(tags=["hero"], starred=true)`,
  `assets_search(min_score=4)`. Each hit has a stable authenticated `url` and `thumb_url`; URL stability does not prevent asset expiry. **Find by meaning (0.9.20).** When the person DESCRIBES an earlier work ("上次那张海边夕阳的", "the one with the red umbrella") search with their own words first: `assets_search(query="semantic:海边的夕阳")` ranks by what the works show and say (picture + prompt, Chinese or English); everything after `semantic:` is the sentence, plain words / `seed:` / `preset:` / `tag:` before it and every filter (`since`, `service`, `starred`, ...) still narrow it. Found a close one: widen with `assets_search(query="like:as-…")` (works that look like that one), or `like:as-… semantic:<words>` for both. Do not guess prompt keywords instead of the person's sentence. A reply with `notes` ("keyword results only", "no picture vector yet") means the meaning index has not reached those works yet: say so and fall back to words / dates — never tell the person the work does not exist.
- `asset_get(asset_id)` returns the record + the job (prompt, seed, params, and since 0.6.0 `params.prompt_id` when the prompt came from
  `prompt_rewrite`) — enough to re-submit the same seed on a final preset without guessing. `presign=true` adds a presigned URL (about 1 hour by default; for anything long-lived keep the stable `url`).
- `asset_tag(asset_id, add=["hero","ep1"], starred=true, collection="game-art")` marks keepers; untagged drafts expire after 7 days.
- `asset_set_in_library(asset_id, in_library=false)` hides one of YOUR OWN works (hidden = not in the library): `assets_search` and every page leave it out (`assets_search(include_hidden=true)` lists your hidden ones), `asset_get` by id still reads it; `in_library=true` brings it back. A tag named `hidden` means nothing. Test / probe pictures: `asset_tag(add=["e2e-probe"])` + `asset_set_in_library(in_library=false)`; the daily sweep deletes those once a day old.
- `asset_again(asset_id)` makes one of YOUR OWN works again: a new job with the same service, preset, words and parameters and a NEW seed; returns the new `job_id` (poll with `job_wait`). Each call starts one more job (same scope and quota as the original submit); speech (its words are not kept), a cover, an upload or a raw workflow output answers `invalid_argument`. To keep the old seed, submit it yourself (the seed is in `asset_get`). `assets_search(include_hidden=true)` lists your hidden works first, latest hide first (`hidden_at`; a «recently deleted» view); every record carries `hidden_at` (null = in the library) and `expires_at`.
- `asset_delete(asset_ids=[...], dry_run=true)` (scope `assets.delete_private`, granted by name to a household token only; hidden otherwise) deletes the caller's OWN private works for good, the private works made from them (`include_derived`) and the words that made them; no undo — always `dry_run=true` first, show the person the per-id answer (would_delete / not_found / not_private / in_use) and the derived count, and delete only what they confirm.
- `asset_feedback_get(asset_id)` (needs `jobs.read`) returns HUMAN ratings entered in the console; `assets_search(rating="bad")` lists rated failures, `rating="none"` unrated work. Empty ratings mean no human feedback, not poor quality. Machine review uses separate scores.
- `asset_rate(asset_id, rating="good"|"ok"|"bad", tags, note)` (administrator key only; a produce key does not have it) records YOUR verdict on a work you actually looked at (reasons: composition, motion, consistency, text_artifacts, audio, other; note <= 280 chars). Rating it again replaces your verdict; never rate on the person's behalf without their word.
- Reuse a matching asset when it satisfies the current request. Scores and metadata identify candidates; claim a hard constraint is met only after inspecting the original media against that same requirement. State any unverified action, sound or visual constraint instead of treating a historical score as delivery approval.

## 2. The loop: draft → review → final
1. **Draft cheaply.** `video_submit(prompt, preset="draft", seconds=5, seed=<fixed>)` or a lottery `seeds=[11, 12, 13, 14]` (≤ 8, one job per
   seed; the PRO 6000 takes the first two, spark-03 the rest). Wait with `job_wait(job_id, timeout_s=55)` (rule 3; never `sleep`); `progress` stays null on the ComfyUI lane — that is not "stuck".
   **Do not end your turn while a job you submitted is still queued/running and you have waits left** — in a non-interactive run (`claude -p`, a hook, a script) there is
   no next turn: keep calling `job_wait` until `done` (or its `next` says to hand over the ticket), then review.
   **Length limits.** `seconds` is at most `presets_list.defaults.effective_max_seconds` (the lower of the instance limit, 15 in production, and the token's own `max_seconds`; the same number `video_submit` cuts to; `creative_params` time rows already carry it). The token limit applies to `video_submit`, `music_submit` and the TOTAL of a `director_run`'s segments; ask within it the first time. A longer value is no longer refused: the service cuts it to the limit and makes the work, and the reply carries `clamped_to` (the length it is really made at), `requested_seconds` and a `seconds_clamped` entry in `warnings` — tell the person the real length and why, and never submit the rest as another job (a director film whose segments cannot all stay above 1 s inside the limit is still refused: `forbidden: seconds > N`). **When the person gave no length, leave `seconds` out** (video default 5 s; a song / BGM default is cut to the token limit with a `seconds_clamped` entry in `warnings`) — do not invent a number.
   Prompt text: write it yourself (see `video-prompting`) or pass `prompt_id` from `prompt_rewrite`; `rewrite="auto"` on `draft` runs the
   deterministic check + rewrite for you and FAILS the call (nothing generated) when no valid prompt comes out. Leave `rewrite` unset to send
   your words untouched (the pre-0.6.0 behaviour). Optional `idempotency_key` makes a retried call replay the first answer instead of paying twice. The same key with DIFFERENT arguments is refused (error code idempotency_conflict), never answered with the first result; `image_submit` / `image_edit` / `music_submit` take the key too. Since 0.9.4 `video_submit` also takes `sound` (`silent` drops the audio track; `ambient` / `dialogue` / `auto` are written by the rewrite), `score` (background music, off by default) and `first_frame` (start from a picture, draft / fast): any sound or score runs the rewrite, `rewrite=off` is allowed only with `sound=silent`; `image_submit` takes `n` (1..4 pictures, seeds seed, seed+1…). `creative_params` is the form declaration for people's create pages, not needed to simply make something.
2. **Review.** `video_review(source=<as-… or job_id>)` / `image_review(source=<as-… or job_id>)` (pass the `as-…` id straight in — do NOT `asset_get` / `*_fetch` first; the job need not be fetched either) → five 1–5 scores + `overall` + one suggestion from the Qwen vision
   lane. Check the original brief as well as the score: sampled JPEGs cannot certify sound, a full action, or human taste. `reverse_prompt(source, style="h3"|"sd"|"plain")` describes an image.
   *Levels (0.7.53):* a multi-shot film comes back with 10–28 dB steps at the cuts, ~50 ms holes at every join and the odd shot clipping — H3 renders each shot's audio alone; level wording changed nothing in two same-seed re-renders (C04 v3, S9 v2; n=2). Finish with `video_audio_level(source=<run or asset>)`: one measured gain per shot (true-peak headroom kept) and `edge_fade_s` (default 0.15 s) fade-out/fade-in around every cut — that alone was "完全 OK" on C04 (user 2026-09-17). **No bed by default**: looping a slice of the film's own audio (`bed_from_shot`) spread the model's wrong shot-1 texture over the whole film and is not recommended; a generated room tone (`ambience=`, `music_submit` preset sfx, "constant, no hum, no events") is opt-in and its content is a taste decision — listen to the scene first, keep it neutral and quiet (`bed_db` −6 or lower). One music track goes under the whole film with `music=` (never per-segment `non_diegetic_music`). The result reports `cut_holes` and `mix_true_peak_dbtp` (≤ −2). If the ambience IS the scene (rain, wind, traffic as the only sound for 30 s), no post pass fixes it: redesign the brief (S9 2026-09-17 — ambience as texture under music/dialogue, fading out, not as the subject).
   *Fast tier (0.7.48):* `video_upscale(source=<asset or job>)` upscales a FINISHED clip 2x with a SPAN model in ~2 min, joins and audio untouched, sharpness ≈2x the draft (a native re-render is ≈4x and ~1 h; `reference/c03-short-20260915/README.md`) — for previews and social sizes, not the showcase final. *Smoother motion:* `video_interpolate(source=<asset or job>, multiplier=2, model="fast")` raises the frame rate of a FINISHED clip (24 fps x2 = 48 fps; `multiplier` 2, 3 or 4; `model` fast | quality | large-motion for big movement), same length, audio kept; the output rate may not pass 120 fps, and a refusal says the largest multiplier that source allows. It runs only where the interpolation weights are installed; if no node has them it says so at once.
3. **Final with the same seed.** Re-submit the approved text with the SAME seed on `fast` (everyday) or `quality` (one candidate, never iterate);
   a `prompt_id` written for `draft` is accepted unchanged on `fast`/`daily`/`quality` (same 5 s); anything else is refused, never re-rewritten.
   Fix missing actions, wrong references or style drift before final rendering; a larger preset is not a repair operation. Recheck the final itself. **Auto-final (0.9.21).** When the person wants a finished video (not "just a draft / preview / lottery") and the draft's `video_review` passes — `parsed: true`, `overall_raw` (else `overall`) ≥ 3.5 (the storyboard gate default), no axis ≤ 2, and the `suggestion` names nothing that breaks the brief — submit the `fast` final with the same seed and text yourself, once, with an `idempotency_key`; do not wait for an "OK". **The final carries the draft's privacy marking**: pass the same `private` value the draft has (read it from `asset_get`; a `prompt_id` from a private source inherits it) — a draft you cannot read the marking of, or a private one you cannot repeat the marking for, is not auto-finalised: deliver the draft and let the person say go. From a lottery only the best seed goes. Never auto-submit `quality` (only when the person asks for it, one candidate) and never a second final for a draft that already has one; a failed review gets one fix-and-redraft, not a final. Say in the delivery that the final was made automatically.
4. **Deliver.** The finished `job_wait` reply already carries `asset_id`; `video_fetch(job_id)` adds `url` (temporary browser link) and the authenticated stable `asset_url`. Give the user the `asset_id` (the work number) and `url` unchanged; keep `asset_id`/`job_id` for reuse. A final you deliver (made by you in this turn, for this person) is starred by you: `asset_tag(asset_id, starred=true)`, then one sentence "已收藏，不要就说" (`asset_tag(asset_id, starred=false)` on request). Never star a draft, a reused older work, another person's work, or a private one (`private: true`; keeping it past the 7-day expiry is the person's word); an unstarred draft may expire after 7 days. Media input and link contracts: `../_shared/media-inputs.md`.
   **A link is the film it names (0.7.54, from the C04 chain trial).** While the final render is still `running`, answer "成片链接" with
   its `run_id`/`job_id`, elapsed time and ETA — never hand over the draft URL as the finished film. If you do include the draft's URL
   for reference, label it 草稿 in the same sentence. After `*_fetch` on the final, deliver that URL and say which version it is.
A TRANSPARENT PNG goes to `preset="qi21-rgba"` before every image route below, whatever model or speed is named (it is the only preset that outputs alpha; cutting out an EXISTING picture stays `image_edit`). Images — pick the ROUTE first, first match wins (`presets_list(brief=true).image_guide`), after two overrides that the PERSON decides for a NEW picture (an edit of an existing one stays `image_edit`): they name the model ("Qwen" / 千问 → `qi21-*`, `qi21-text` when there are words; "Krea" → `krea-*`) or ask for fast / a draft (→ `preset="krea-fast"`, 1 MP, unless the picture must carry words). Then: (1) a real-looking PHOTO that must carry exact words (shop front, product poster, menu board, ad) = TWO calls: `image_submit(prompt, preset="krea-default", aspect_ratio="2:3", seed)` for the photo with NO text in it, then `image_edit(images=[<that job_id>], instruction='add the title "…" and the date "…" in the empty sky')` (Krea2 alone misspells Chinese; `qi21-text` alone looks less like a photo); (2) typography IS the picture (graphic poster, flyer, infographic, UI, menu design, an illustration whose words must be right) → `preset="qi21-text"`, quote the words; (3) combine / keep / change EXISTING pictures → `image_edit`; (4) many named elements with exact counts / left-right positions → `preset="qi21-t2i"` (`"qi21-scene"` for 3:2 wide); (5) everything else without exact text — photo, portrait, product, food, anime, concept art, landscape, night, crowds / cities / big scenes → `krea-default` (2 MP on the PRO 6000; `krea-169` = wide; Krea is the quality default, not a draft); exception: a NON-PHOTOREAL fantasy / concept-art big scene at grand scale → `qi21-scene` (a photoreal big scene and a single concept-art subject stay Krea). **Posters and covers are portrait 2:3** (`aspect_ratio="2:3"`; Krea: 1184×1760 on the PRO 6000, 832×1248 on a GB10; `width`/`height` pin one size everywhere). Also `"qi21-quality"` (one hard final on Qwen). Every `qi21-*` preset except `qi21-rgba` rewrites with the official Qwen prompt enhancer first (0.8.6; +15–45 s; `rewrite="off"` skips it; `sent_prompt` in the status is what the model got); wait with `job_wait` (rule 3), give the person the `asset_id`; `image_fetch(job_id)` only for a download URL. `n` (1..4) gives `{batch, job_ids}`: wait on each id.
Raw ComfyUI graphs: `workflow_submit(graph_json, overrides)` → `workflow_status` / `workflow_fetch` — ask the operator for a template first.

## 3. Speech and translation (synchronous, this skill's job)
- `tts(text, voice, lang)` → WAV asset. Voices are presets (`presets_list` → `tts_voices`): `default`, `calm`, `news`, `story-female`,
  `story-male`, `energetic`; two additional cloud voices are listed but unavailable. Current production cap: 2000 characters per call; split longer speech by scene/sentence.
  Speed and warm-up options are not MCP parameters; inspect the TTS schema and live presets.
- `translate(text, dst="en", src=None)` via Hy-MT2; `dst` is the target language (default zh), `src` is auto-detected when omitted. Only the languages in the tool's description are taken (zh, zh-Hans, zh-Hant, yue, en, ja, ko, fr, de, es, ru, ar and more; names and region forms like en-US / zh-CN also work); anything else comes back `invalid_argument` with `field` (src or dst) and the `supported` list — pick one from it, do not retry the same word. **Reading text in a picture / timing a recording** (0.9.6): `ocr(source)` returns `{text, engine, degraded}` for one picture (an `as-…` asset id, an image job_id or an allow-listed URL) — or `ocr(data_base64=…)` with the picture's own bytes (png / jpeg / webp / heic, <= 8 MiB; exactly one of the two; held in memory for that call only, not stored, not put in the library, never sent to a cloud engine: no `asset_upload` step needed); `align(audio, text, lang="zh")` returns `{items: [{text, start_ms, end_ms}], engine, degraded}` for a recording of at most 20 s (an asset, a tts / music / video job_id or a URL) and the words spoken in it. Both need a key that holds the `ocr` / `align` scope (or admin). Use `ocr` when the person asks what a screenshot / photo / scan SAYS (not to judge a generated image: that is `image_review`); use `align` for subtitles or "jump to this word". The main OCR model loads on demand: the first call after ~10 idle minutes may take 10–30 s and it yields while the drawing machine is busy. `degraded: true` = the CPU fallback engine read it, not the main model (fine for search, may miss small or hard characters — say so if exactness matters; for exact text try again later with `fallback=false`). A transparent PNG / WebP is read on a white background. `degraded_reason` (absent on a normal answer) with `degraded: true`; the text is always whole: `repetition_suspect` / `repetition_high` = it repeats the same characters a great deal, as a stuck recognizer does (it may be a real table) — say it may not be read reliably; `budget_exhausted` / `budget_suspect` = the recognizer stopped (probably) at its output limit — say the end of a long page may be missing. `blank_input: true` with empty text = the picture is one solid colour (no recognizer was asked). Errors ending in (retry_after_s=N) are temporary: for `model_warming` / `service_busy` tell the person "识别模型正在加载 / 画图机正忙，N 秒后再试"; for `backend_unreachable` / `backend_timeout` tell them "识别服务暂时连不上 / 超时，N 秒后再试"; retry once after N s and never report "no text found" for these. `unsupported_media`, `input_too_large`, `not_alignable`, `invalid_argument`, `private` will not change on retry: say what is wrong with the input; `invalid_argument` saying 图里没有读出文字 means the engine read nothing from this picture (say the picture seems to hold no readable text). Replies carry no links.
- Voice cloning (`voice_enroll`) and lip-sync (`lipsync`) are cloud-only tools that appear only when their entry is keyed — today none is.

## 4. Jobs, recovery, presets
- `jobs_list(limit, service, status)` for an overview (`service` = video / image / music / tts / workflow / shot / embed); to find an earlier song or sound use `assets_search(service="music")`; `presets_list` for the live presets / voices / models / cloud entries (`available` flag).
- `job_recover(job_id, action=attach|resubmit|abandon, backend_id)` (admin) resolves `submission_unknown`, `cancel_pending`,
  `cancel_unconfirmed`. **Never just re-submit such a job** — the node may be generating it; check the node, then attach / resubmit / abandon.
- Administrator tools (scope `admin`, hidden from every other key): `ops_presets(file, version_id)` reads the preset files and their versions, `ops_preset_validate(file, content)` checks a text without writing, `ops_registry_file()` reads the whole registry file, `ops_upstream_keys(name)` shows the upstream keys MASKED (never a value), `ops_feedback_export(since, history, after_id, upto_id)` pages the human verdicts. A change is only PROPOSED: `ops_preset_propose(file, expected_digest, content=... | version_id=..., note)` and `ops_registry_propose(content, expected_digest, note)` write nothing until a person approves (console 需人拍板 or the command line); follow with `ops_proposals(op_id)` and tell the person it waits for them. Administrator READ tools (nothing written; no address or key value in an answer): `ops_status()`, `ops_infra(service)`, `ops_lanes()`, `ops_jobs_live()`, `ops_attention()` (what waits for a person), `ops_runs(run_id, key)`, `ops_tokens()`, `ops_token_get(token_id, section)`, `ops_accounts(account_id)`, `ops_usage(token_id, account_id, days)`, `ops_cost(token_id, account_id, days)`, `ops_audit(since, action, token_name, account_name, via, limit, before_id)`, `ops_registry_get()`, `ops_dispatch_holds(hold_id, active)`, `ops_howto(client)`, `prompt_asset_list(group, state, risk, q)`, `prompt_asset_get(id)`, `prompt_asset_revs(id, before)`, `prompt_asset_preview(id, candidate, context)`. A private film shows as its closed row; say what you read, never guess a number. Administrator CHANGES that undo cleanly (audited, an MCP key is never "freshly signed in", so anything a person must confirm stays in the console): `ops_dispatch_hold(services, reason, until, allow_gap, op_id)` / `ops_dispatch_release(hold_ids, reason, force, op_id)`, `ops_asset_hide(asset_id)`, `ops_token_patch(token_id, note)` (the note only), `ops_run_cancel(run_id, reason)`; two more reads: `ops_job_get(job_id)` and `ops_jobs_history(state, key, cursor, limit)`. `ops_lane_set(lane, preset, reason, supersede)` switches a lane's scale (only a lane whose machine offers the write contract; it waits while someone at home is talking — `conflict`, try later; `state: done` = in effect, `pending` = takes effect when the lane is free; undo = switch back to the `from` preset). `ops_probe(service)` and `ops_cluster_tick()` refresh the probe / machine readings now (read only towards the machines).
- Cloud presets have `cloud: true` and `available` on each video/image/music/voice entry; there is no required top-level `cloud` section. A disabled entry is not callable. Follow the user's budget for paid generations.
- `compliance_review(source)` / `compliance_status(job_id)` = the licensed publish gate (cloud, only when keyed).

- **Offline embedding batches (0.7.55)** — `embed_batch_submit(items, model?, tag?)` for bulk ingestion (family album, project corpora):
  items are texts or `{type: image|video, source: asset id / job id / allow-listed URL / data: URL, text?: caption}`. It returns an
  `embed-…` job at once and runs ONLY while the film node sharing the embedding GPU is idle (a WeMM burst made an H3 draft 2× slower,
  measured 2026-09-19), so a big batch may pause for an hour behind a film job — that is by design, not a fault. Do not `job_wait`
  on a large batch: submit, tell the user the id, come back later with `embed_batch_status` / `jobs_list(service=embed)`, then
  `embed_batch_fetch` for the JSONL vectors (one line per item). For ONE query-time embedding use the gateway `/v1/embeddings`.

## 5. Etiquette
Always pass and record a `seed`. On `backend_unreachable` / `queue_full` wait and retry, never spam. `quality` is for one approved candidate.
For a missing tool, check the current surface, permissions, disabled cloud entries and any planning-only restriction first. Ask for `/mcp` reconnection only when an expected connected tool is actually unavailable; never call a hidden tool by guessing its name.
